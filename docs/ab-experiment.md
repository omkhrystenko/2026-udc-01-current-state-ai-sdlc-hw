# A/B experiment — Task 4 (bonus)

Одна й та сама задача («лічильник» з Task 2), два промпти.

## Промпт A — базовий
```
зроби лічильник на Next.js
```

## Промпт B — структурований
```
Роль: ти senior React/Next.js розробник.
Контекст: проєкт Next.js 16 (App Router) + TypeScript + Tailwind у теці app/.
Конвенції з AGENTS.md: функціональні компоненти PascalCase, лише Tailwind,
тексти українською.

Задача: компонент-лічильник.

Acceptance criteria:
1. Число, початкове 0.
2. Кнопка "+1" збільшує.
3. Кнопка "-1" зменшує.
4. Кнопка "Скинути" -> 0.
5. Число не стає від'ємним (на 0 кнопка "-1" неактивна).

Обмеження: без сторонніх бібліотек, без окремих CSS-файлів.
Формат: один файл app/app/components/Counter.tsx + підключити у page.tsx.
Спершу покажи план, потім код.
```

## Результати

| Критерій | Промпт A (базовий) | Промпт B (структурований) |
|---|---|---|
| Якість | працює, але стиль/нейминг довільні; межові випадки не враховані | відповідає всім 5 acceptance criteria й конвенціям |
| Захист від від'ємних чисел | відсутній (не просили) | є (пункт 5 критеріїв) |
| Кількість ітерацій | ~2-3 (правки стилю, поведінки, мови) | 1 (з першого проходу) |
| Токени | більше (зайві раунди правок) | менше (менше переробок) |
| Передбачуваність | низька | висока |

## Висновок
Структурований промпт (роль + контекст + обмеження + acceptance criteria +
формат) дав коректний результат з першого проходу й заощадив ітерації та
токени. Базовий промпт «зроби X» працює, але залишає рішення на модель —
довільний стиль, англомовні тексти, відсутні межові випадки — і потребує
кількох додаткових раундів правок. Чіткі acceptance criteria *до* коду — головний
важіль і якості, і вартості.
